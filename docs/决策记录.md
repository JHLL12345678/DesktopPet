## ADR-001 · 语言选 C#

- **日期**：2026-11-10
- **状态**：已定
- **背景**：用户暂定 C#，对实现思路暂无头绪。
- **决定**：用 C# 实现，不换语言。
- **理由**：Windows 桌面常驻程序的最优解之一；VS 工具链现成；后续要接 Win32 API 也方便。
- **后果**：锁定 Windows 平台（当前需求就是 Windows，无损失）。

## ADR-002 · UI 宿主选 WPF（而非 WinForms）

- **日期**：2026-11-10
- **状态**：**已定**（2026-11-10 用户确认选 WPF）
- **背景**：桌宠的核心难点是「透明无边框悬浮窗 + 平滑动画」，不是普通表单。
- **决定**：`DesktopPet` 用 WPF；WinForms 作为备选方案保留（不再推进）。
- **理由**：
  - WPF 的逐像素透明是窗口属性级别的开关，抗锯齿边缘、柔和阴影天然正常；
  - 动画、缩放、DPI 支持成熟；
  - WinForms 的 `TransparencyKey` 抠色只适合硬边像素风，柔和边缘会出彩边；
  - WinForms 要做到同等效果需手写 `UpdateLayeredWindow` 互操作，成本更高。
- **代价**：WPF 透明窗口会走软件渲染（小窗口无影响）；需要学一点 XAML。
- **替代方案**：WinForms + `TransparencyKey`（像素风、想用设计器时可选）。若改选，本 ADR 改为「已定：WinForms」，Core 层不受影响。
- **影响范围**：仅 `DesktopPet` 项目；`DesktopPet.Core` 不变。

## ADR-003 · 目标框架 `net10.0-windows`

- **日期**：2026-11-10
- **状态**：提议
- **背景**：机器 A 只装了 .NET SDK 10.0.401；桌面运行时同时存在 8.0.31 与 10.0.12。
- **决定（建议）**：目标框架 `net10.0-windows`，用 `global.json` 锁 SDK 主版本。
- **理由**：SDK 自带对应 targeting pack，无额外安装；.NET 10 为 LTS。
- **代价**：其他机器若只有 .NET 8 SDK，需要装 SDK 10 或临时降 target。
- **替代方案**：`net8.0-windows`（更普适，但要确认 8.x targeting pack 在位）。

## ADR-004 · 分三层：Core / App / Tests

- **日期**：2026-11-10
- **状态**：提议
- **决定**：`DesktopPet.Core`（零 UI 依赖） + `DesktopPet`（宿主） + `DesktopPet.Core.Tests`（xUnit）。
- **理由**：状态机与物理逻辑可单测；UI 可替换；避免「所有东西塞进窗体后台代码」的典型烂尾。
- **代价**：初期多一点样板代码；需要定义渲染/屏幕/时钟接口。
- **影响**：所有新功能默认先落 Core，再由 App 消费。

## ADR-005 · 动画用精灵图集 + 元数据

- **日期**：2026-11-10
- **状态**：提议
- **决定**：单张图集 PNG + `meta.json`（帧尺寸、动画段、fps、循环、锚点），运行时切帧。
- **理由**：文件少、加载快、便于打包；比 GIF 可控（GIF 无法精确控帧、有色带）；比逐帧 PNG 少一堆 IO。
- **代价**：需要美术按固定栅格出图；需自己做帧播放器。
- **替代**：逐帧 PNG（简单但文件多）；Live2D（效果最好，但引入第三方运行时，后期再议）。

## ADR-007 · 用 Git 做跨机器同步

- **日期**：2026-11-10
- **状态**：提议（**前置条件未满足：机器 A 未安装 Git**）
- **背景**：会话会在多台电脑上进行，需要代码与上下文文档同步。
- **决定**：`G:\桌宠` 建为 Git 仓库，`AI_CONTEXT.md` 与 `docs/` 一并入库；远程仓库待定（GitHub / Gitee / 自建）。
- **理由**：有历史、可回滚、可对比；上下文文档跟着代码走，不会分叉。
- **代价**：需要先装 Git 并学会最基础的 `pull / commit / push`。
- **替代**：网盘同步整个目录（简单，但冲突难处理，且会把 `bin/obj` 一起同步）。

## ADR-008 · 目录采用扁平布局（不用 src/ tests/ 分层）

- **日期**：2026-11-10
- **状态**：已定
- **背景**：原计划用 `src\`、`tests\` 分层。但用户在 Visual Studio 新建项目时，VS 默认把项目建在解决方案同级目录，要放进 `src\` 需要额外改路径或事后移动，增加出错概率。
- **决定**：`G:\桌宠` 根目录直接放 `DesktopPet.sln`、`DesktopPet.App\`、`DesktopPet.Core\`、`DesktopPet.Core.Tests\`。
- **理由**：与 VS 默认行为一致，降低新手操作成本；项目变多时再迁移也不影响编译。
- **代价**：仓库根目录文件数略多；与部分团队的 `src/` 习惯不同。
- **影响**：所有文档中的路径以此为准。
