# 桌宠 · 可行技术路线

> **一句话结论**：C# + .NET 10 + WPF 做宿主窗口，Core 类库装纯逻辑，精灵图集做动画，`dotnet publish` 出单文件 exe；代码全部在 `G:\桌宠`，用 Git 跨机器同步。
>
> 本文只讲路线与取舍，**不含实现代码**。具体某一步怎么做，等推进到那一步再展开。

---

## 一、选型与对比

| 层 | 选择 | 备选 | 理由 |
|---|---|---|---|
| 语言 | C# | — | 用户暂定；VS 与桌面生态最顺 |
| 运行时 | .NET 10（`net10.0-windows`） | .NET 8 LTS | 本机只装了 SDK 10；Win10 1809+ 均支持 |
| UI 宿主 | **WPF** | WinForms / WinUI 3 / Avalonia | 逐像素透明、动画、DPI 开箱即用 |
| 动画 | 精灵图集 + 时间驱动帧循环 | GIF / 逐帧 PNG / Live2D | 可控、可打包、性能稳定 |
| 逻辑 | 分层：Core 无 UI 依赖 | 全塞进窗体 | 可单测、可换 UI、可复用 |
| 打包 | 自包含单文件 | 依赖已装运行时 | 干净机器双击即用 |
| 同步 | Git（待安装） | 网盘同步 | 有历史、可回滚、可分支 |

### WPF vs WinForms（唯一需要用户拍板的地方）

- **WPF**：窗口设「无边框 + 允许透明 + 透明背景」即得**逐像素 alpha**——抗锯齿边缘、柔和阴影、任意缩放都正常；Storyboard 做位移/缩放/淡入淡出；30/60fps 帧循环简单；XAML 上手需学一点。
  代价：WPF 的透明窗口会退化到**软件渲染**（GPU 加速失效）。宠物窗通常只有 200×300 级别，现代 CPU 完全够用；将来真做大尺寸特效再换方案。
- **WinForms**：设计器最熟、上手最快。但透明只有两条路：
  1. `TransparencyKey` 抠色——只适合**像素风硬边**，抗锯齿边缘会留一圈彩边/白边；
  2. `WS_EX_LAYERED` + `UpdateLayeredWindow` 手写 P/Invoke——效果等同 WPF，但代码量、坑、调试成本都高得多。
- **结论：推荐 WPF。** 如果确定走像素风、且更想用 WinForms 设计器，WinForms + TransparencyKey 也能快速出第一版；因为 Core 与 UI 解耦，**以后换 UI 不影响逻辑**。

### 为什么不选别的

- **WinUI 3 / MAUI**：逐像素透明窗口支持差，桌宠这种「无边框悬浮窗」恰恰是它们的短板。
- **Avalonia**：跨平台是优点，但 Windows 上的透明窗口同样要靠 Win32 互操作；当前只做 Windows，没必要。
- **Electron / Unity**：体积大、启动慢，桌宠这种轻量常驻程序不合适。

## 二、总体架构

```
┌──────────────────────────────────────────────────┐
│ DesktopPet.App （WPF, net10.0-windows）           │
│  ├ PetWindow        无边框 / 透明 / 置顶 / 不激活   │
│  ├ SpriteRenderer   图集切帧 + 缩放 + 插值模式      │
│  ├ TrayIcon         托盘菜单（显示/隐藏/设置/退出）  │
│  ├ InputHandler     拖拽 / 单击 / 双击 / 右键       │
│  ├ ScreenService    多屏工作区 / DPI / 全屏检测     │
│  └ AppHost          单实例 / 开机自启 / 生命周期     │
└───────────────────┬──────────────────────────────┘
                    │ 只通过接口与事件通信
┌───────────────────┴──────────────────────────────┐
│ DesktopPet.Core （net10.0，零 UI 依赖）            │
│  ├ Brain          行为状态机 + 决策 tick（低频）    │
│  ├ Physics        重力 / 落地 / 边界 / 惯性 / 阻尼   │
│  ├ Animation      帧序列 / 播放器 / 锚点 / 循环      │
│  ├ PetState       心情 / 精力 / 时间感知            │
│  └ Config         配置模型 + 校验 + 默认值           │
└───────────────────┬──────────────────────────────┘
                    ▲ 可直接单元测试
        DesktopPet.Core.Tests （xUnit）
```

**核心思想**：把「怎么画、在哪个屏幕、现在几点」抽象成接口（渲染面、屏幕信息、时钟），Core 只做纯计算。
好处：行为逻辑能无窗口单测；换 WPF/WinForms 不用重写；后续加「心情系统」不会烂成一锅粥。

**两个独立的节拍**（很重要，别混成一团）：

- **决策 tick**：低频（约 5–10 Hz），由 Brain 决定「现在该切什么状态」。
- **渲染 tick**：高频（30–60 fps），由动画播放器推进帧、物理更新位置。

混在一起会导致帧率一变行为就变，而且没法单独调。

## 三、关键技术点（每条：要解决什么 / 用什么 / 坑在哪）

### 1. 透明、无边框、置顶、不进任务栏
**手段**：窗口无边框 + 允许透明 + 背景透明 + 置顶 + 不显示在任务栏 + 不可缩放。
**坑**：透明窗口尽量小（软件渲染）；「置顶」必须能被临时关掉，否则用户看视频/打游戏会被烦到。

### 2. 不抢焦点
点宠物不应该让用户正在打字的输入框失焦。
**手段**：给窗口加「不激活」扩展样式（`WS_EX_NOACTIVATE`），鼠标事件照收。
**坑**：加了之后收不到键盘事件——需要键盘交互时再单独处理焦点。

### 3. 透明区域点击穿透
矩形窗口的空白区域会挡住底下的桌面图标。
**手段**：维护当前帧的 alpha 掩码，在命中测试消息（`WM_NCHITTEST`）中对透明像素返回穿透。
**坑**：逐像素判断有成本 → 只在换帧时重算，或按 16×16 分块粗判。

### 4. 拖拽与物理
- 拖动：按下时捕获鼠标 → 跟随移动 → 松开。
- 松手：取最近几帧位移算出**初速度**，进入下落 + 阻尼 + 触地反弹。
- 地面：**当前显示器的工作区底边**，不是屏幕底边（否则会压在任务栏下面）。
- 左右：屏幕边缘夹紧，可加「贴边行走」。

**坑**：高 DPI 下直接改窗口 Left/Top 会抖；要按屏幕坐标换算，并保持「抓取点偏移」跟手。

### 5. 多显示器 / 高 DPI / 任务栏
- `SystemParameters.WorkArea` **只有主屏** → 必须用 `MonitorFromWindow` + `GetMonitorInfo` 拿每块屏的 `rcWork`。
- 应用清单声明 **Per-Monitor V2** DPI 感知，否则跨屏拖动会错位。
- 任务栏自动隐藏会改变工作区 → 监听显示设置变更消息。
- **坑**：不同缩放比例的屏幕之间拖动，坐标要按目标屏 DPI 换算。

### 6. 全屏检测（不打扰原则）
前台窗口矩形 == 显示器矩形 → 判定全屏（游戏/视频），宠物隐藏；退出全屏后恢复。

### 7. 托盘 / 单实例 / 开机自启
- 托盘：WPF 没有内置 NotifyIcon，用社区库（如 Hardcodet.NotifyIcon.Wpf）或引用 WinForms 的 NotifyIcon。
- 单实例：命名 Mutex；第二个实例把「显示」消息转给第一个再退出。
- 自启：写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，无需管理员权限。

### 8. 动画与性能
- 切帧：用 `ImageBrush` 的 Viewbox 显示图集子矩形，**不产生每帧新位图**；或预切 `CroppedBitmap` 缓存（内存换 CPU）。
- 计时：跟随 `CompositionTarget.Rendering` 做固定步长累加，比 `DispatcherTimer` 稳。
- 像素风缩放用最近邻插值；柔和画风用高质量插值。
- 目标：空闲 CPU < 1%，动画中 < 3%，内存 < 120 MB。

### 9. 配置持久化
`%AppData%\DesktopPet\config.json`：位置、缩放、音量、自启、当前角色包。
读：启动时一次；写：变更时 + 退出时，**原子写**（先写临时文件再替换），避免断电写坏。

### 10. 打包发布
`dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true`。
**坑**：WPF 不支持裁剪（trimming）；单文件自解压可能被杀软误报，必要时改用「文件夹 + 压缩包」发布。

## 四、里程碑（一次只做一个）

| 阶段 | 目标 | 主要产出 | 验收标准 | 预估 |
|---|---|---|---|---|
| **M0 地基** | 能编译、能提交 | 解决方案 + 3 个项目 + `global.json` + `Directory.Build.props` + `.gitignore` + Git 仓库 | `dotnet build` 通过；`dotnet test` 跑通空测试；首次 commit | 0.5 天 |
| **M1 透明窗** | 看得见、拖得动、关得掉 | 无边框透明置顶窗口（不激活/不进任务栏）+ 静态图 + 拖动 + 托盘退出 + 位置记忆 | 拖动跟手；点它不夺焦点；重启回到原位 | 1 天 |
| **M2 动起来** | 有动画 | 图集 + 元数据 + 帧播放器（30fps）+ Idle/Walk 两套 + 调试快捷键 | 动画流畅；空闲 CPU < 1%，动画 < 3%；内存无增长 | 1–2 天 |
| **M3 有脑子** | 自己会动 | 状态机 + 决策 tick + 重力/落地/边缘 + 多屏工作区 | 静置 5 分钟不呆板也不乱跑；拖出屏幕会被拉回；换分辨率不跑丢 | 2–3 天 |
| **M4 手感** | 交互像活的 | 点击反应 + 右键菜单 + 甩动惯性 + 透明区穿透 + 全屏自动隐藏 + 自启 + 单实例 | 视频全屏时自动隐藏；透明白区点击能穿透 | 2–3 天 |
| **M5 内容** | 有情绪、可换肤 | 心情/精力、时间感知（晚上犯困）、音效、角色资源包切换 | 换角色包只改配置不改代码 | 3–5 天 |
| **M6 发布** | 能给别人用 | 自包含单文件 exe + 图标 + 版本号 + 使用说明 | 干净机器双击即用 | 1 天 |

> 前面三个阶段是「骨架」，M3 之后才开始变好玩。**不要在 M1 就纠结素材好不好看**，先用一张临时图跑通链路。

## 五、美术资源规范（先定，后面省事）

- 每个角色一个目录：`assets/pets/<角色id>/`，内含一张图集 PNG + 一个 `meta.json`。
- `meta.json` 需描述：帧宽、帧高、列数、每个动画的「起始帧 + 帧数 + fps + 是否循环」、画布锚点。
- **所有帧统一画布尺寸，锚点固定在脚底中心** → 走路/站立切换时不会「跳一下」。
- 透明 PNG，导出时关闭「杂边/预乘」相关的黑边选项。
- 基准 1 倍尺寸（例如 128×160），运行时按整数倍缩放，像素风才不糊。

## 六、风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| 透明窗口在全屏游戏/视频上置顶 | 用户觉得烦，直接卸载 | 全屏检测自动隐藏；托盘一键「隐身」 |
| 多屏不同 DPI 坐标错位 | 拖到另一块屏就跳 | Per-Monitor V2 + 按目标屏换算 |
| WPF 透明窗口失去 GPU 加速 | 大尺寸时掉帧 | 控制窗口尺寸；必要时改分层窗口/D3D 方案 |
| 单文件发布被杀软误报 | 用户装不上 | 备用「文件夹 + zip」发布；加数字签名（后期） |
| 美术素材版权 | 无法公开发布 | 只用自制/授权素材，记录来源 |
| 目标机没有 .NET 运行时 | 双击打不开 | 自包含发布 |
| 项目盘为 exFAT | 构建偏慢、无硬链接、无日志式保护、Git 报 dubious ownership | 加 `safe.directory` 例外；重要节点打 Git 标签；或把项目挪到 NTFS |
| 会话跨机器、上下文丢失 | 重复劳动、推倒重来 | `AI_CONTEXT.md` + `docs/` 随仓库同步，每次会话后更新 |

## 七、M0 的具体动作（等你确认 UI 栈后执行，仍不写业务代码）

1. 装 Git 并配置 `user.name` / `user.email`（当前机器没有）。
2. 建解决方案与三个项目：Core 类库、App（WPF 或 WinForms）、Tests。
3. 加 `global.json` 锁 SDK 主版本；`Directory.Build.props` 统一 `Nullable` / `LangVersion` / 版本号。
4. `.gitignore` 排除 `bin/`、`obj/`、`.vs/`。
5. 空跑 `dotnet build` 与 `dotnet test`，确认工具链正常。
6. 首次提交，打 tag `m0`。
